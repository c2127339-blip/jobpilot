# 前端开发实习 · 模拟面试问题

## 项目经历

### 1. 在「学生二手交易平台」项目中，你负责的商品展示功能具体是怎么实现的？

- **难度**：简单
- **为什么问**：面试官想确认项目是否是你真实参与，以及你在其中的具体角色和产出。
- **参考答案思路**：按「功能拆分 → 数据获取 → 渲染 → 交互」描述，说明你负责的页面、用到的技术点，突出自己独立完成的部分。

### 2. 这个项目的前端和后端是怎么对接的？接口约定和数据格式是谁来定的？

- **难度**：中等
- **为什么问**：考察你对前后端协作流程的理解，以及是否具备接口调用的实战经验。
- **参考答案思路**：讲清楚 RESTful 接口约定、请求方法、数据格式（JSON）、错误处理，说明你如何配合后端完成数据展示。

### 3. 如果商品列表数据量很大，你的分页或加载方案是什么？

- **难度**：困难
- **为什么问**：考察你是否考虑过真实场景下的性能问题，而非停留在功能实现。
- **参考答案思路**：可谈分页加载 / 触底加载（滚动加载）、图片懒加载、节流防抖等前端优化手段。

## 前端技术

### 1. Vue 和 React 你都接触过，说说你对组件化开发的理解。

- **难度**：简单
- **为什么问**：JD 要求了解 React 或 Vue，面试官想确认你对组件化思想的真实理解，而非只会套用。
- **参考答案思路**：从「组件复用、单一职责、props/state 数据流、组件通信」几个角度展开，结合你的项目举例。

### 2. 解释一下 ES6 中的 const、let 与 var 的区别。

- **难度**：简单
- **为什么问**：JD 要求掌握 ES6+ 语法，这是最基础的考察点，同时考察表达是否清晰。
- **参考答案思路**：从「作用域（块级 vs 函数级）、变量提升、重复声明、const 的引用不可变」几个点作答。

### 3. 浏览器从输入 URL 到页面渲染，发生了什么？

- **难度**：中等
- **为什么问**：加分项提到理解浏览器工作原理，这是前端进阶的经典问题。
- **参考答案思路**：按「DNS 解析 → TCP 连接 → HTTP 请求 → 服务器响应 → HTML 解析 → DOM/CSSOM 构建 → 渲染树 → 布局绘制」串起来讲。

### 4. 你在项目里怎么使用 Git？遇到合并冲突怎么处理？

- **难度**：中等
- **为什么问**：JD 要求理解 Git 与团队协作，面试官想了解你是否有多人协作的实践经验。
- **参考答案思路**：讲清楚日常提交流程、分支管理，以及处理冲突的思路（手动解决 / 沟通确认后再提交）。

## 行为面试

### 1. 介绍一个你遇到过的难题，以及你是怎么解决的。

- **难度**：简单
- **为什么问**：考察你解决问题的思路、主动性和复盘能力，是行为面试的必问题。
- **参考答案思路**：用 STAR 法则：情境（Situation）→ 任务（Task）→ 行动（Action）→ 结果（Result），尽量选项目中的真实案例。

### 2. 如果后端接口还没写好，你作为前端怎么推进工作？

- **难度**：中等
- **为什么问**：考察你在真实协作场景中的主动性和应变能力。
- **参考答案思路**：可谈用 Mock 数据先行开发、与后端提前约定接口格式、用工具（如 json-server）模拟数据等。

## 岗位匹配

### 1. 你本科是信息与计算科学专业，为什么选择走前端方向？

- **难度**：简单
- **为什么问**：JD 提到「对前端技术有热情」，面试官想确认你的职业动机是否真实。
- **参考答案思路**：结合课程基础、项目中的正反馈、对前端生态的兴趣，表达真实且具体的理由。

### 2. 如果入职后让你先做一段时间的简单页面，你会怎么看待？

- **难度**：中等
- **为什么问**：考察你的态度：是否愿意从基础做起，是否有成长心态。
- **参考答案思路**：表达愿意从基础做起，同时说明会主动把简单任务做规范，并利用时间学习沉淀。

## 简历 vs JD 差距提示

- JD 要求「了解 TypeScript」，简历中未提及，建议补一份 TS 的小型练习项目或说明了解程度。
- JD 加分项提到「Vite / Webpack 构建工具」，可在简历中补充你使用的开发工具链。
- 项目经历可以补充量化成果（如页面数量、日活用户、性能提升），让产出更有说服力。
